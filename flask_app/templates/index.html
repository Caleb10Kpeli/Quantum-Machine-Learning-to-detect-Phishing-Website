Key Finding

{% if results.qsvm_reupload is defined and results.qnn_reupload is defined %}

Starting from the QSVM/QNN above as a fixed baseline, we applied one isolated architectural change to each — data re-uploading (Perez-Salinas et al., 2020): re-encoding the same 6 classical features deeper into the circuit instead of once. Everything else (qubits, data split, training budget, and for the QNN, even the parameter count) was held fixed, so the result is attributable to re-uploading alone.

For the QSVM, repeating the feature map twice improved every metric: {{ "%.1f"|format(results.qsvm_reupload.accuracy * 100) }}% accuracy (vs {{ "%.1f"|format(results.qsvm.accuracy * 100) }}% baseline) and {{ "%.2f"|format(results.qsvm_reupload.f1 * 100) }}% F1 (vs {{ "%.2f"|format(results.qsvm.f1 * 100) }}%). A deeper feature map gives the kernel a richer notion of similarity between URLs.

For the QNN, the same technique did not help — {{ "%.1f"|format(results.qnn_reupload.accuracy * 100) }}% accuracy vs {{ "%.1f"|format(results.qnn.accuracy * 100) }}% baseline, though precision did improve ({{ "%.2f"|format(results.qnn_reupload.precision * 100) }}% vs {{ "%.2f"|format(results.qnn.precision * 100) }}%). With only 200 training samples, the extra re-encoding adds circuit depth without adding new information, and the baseline's single embedding was already sufficient for its 54 trainable parameters to fit the data — a reminder that the same technique doesn't transfer uniformly across model families.

{% elif results.qnn is defined %}

When constrained to the same 6 features and 200 training samples, both quantum models match the Classical SVM (Fair) baseline. The QSVM achieves {{ "%.1f"|format(results.qsvm.accuracy * 100) }}% accuracy with higher precision ({{ "%.2f"|format(results.qsvm.precision * 100) }}% vs {{ "%.2f"|format(results.classical_fair.precision * 100) }}%) — fewer false alarms. The QNN achieves {{ "%.1f"|format(results.qnn.accuracy * 100) }}% accuracy via end-to-end variational training. Note: the live analyser uses the full Classical SVM ({{ "%.1f"|format(results.classical_full.accuracy * 100) }}%), which has 45× more training data and 14× more features than the quantum models.

How It Works

1

Feature Extraction

87 URL-based features are extracted from each link: length, special characters, HTTPS usage, domain age, hyperlink ratios, phishing keywords, and more. Live extraction uses DNS lookups and WHOIS data where available.

2

Quantum Kernel (QSVM)

The top 6 features are angle-encoded into a 6-qubit PennyLane circuit. A ZZ-style feature map computes the quantum kernel K(x,x′) = |⟨φ(x′)|φ(x)⟩|², which is fed into a classical SVM solver.

3

Variational QNN

A second quantum model uses 3 layers of trainable Rot gates with ring CNOT entanglement. The PauliZ expectation value on qubit 0 acts as the classifier output, trained end-to-end with Adam gradient descent.

4

Classical Baseline

An RBF-SVM trained on all 87 features and 9,144 samples provides the gold-standard comparison. The live URL analyser uses this model for instant, high-accuracy predictions.

{% if results.qsvm_reupload is defined or results.qnn_reupload is defined %}
5

Data Re-uploading (v2)

Both quantum models above are re-tested with data re-uploading (Perez-Salinas et al., 2020): the same 6 features are re-encoded deeper into the circuit — twice through the QSVM's feature map, or once per QNN layer — instead of only at the very start. Every other setting (qubits, data split, parameter count) is held fixed, isolating exactly what re-uploading changes.
